## 3. 拟定的只读契约

`PagedG3ReadOnlySourceAdapter` 扩展原只读协议，新增的方法仍然全是读：

| 方法 / 对象 | 必须保证的语义 |
|---|---|
| `begin_scan(after_cursor, access)` | 返回来源 generation、来源 epoch、授权 epoch、主体/范围绑定、扫描起点及上界 |
| `read_page(scan, after_cursor, limit, access)` | 页必须属于同一扫描；声明覆盖的游标区间完整；ACL 过滤可形成空页，但不能静默丢失该主体可见的变更 |
| `validate_scan(scan, access)` | 来源历史或授权变化时拒绝；正式实现需要真实权威层的事务/一致性保证 |
| `authorization_epoch` | 不只覆盖角色授权，还必须覆盖单条事件可见范围改变、删除/撤销导致的可见性变化 |
| `source_generation` | 防止把不同来源历史的游标复用；不是外部可信 C，也不证明不可回滚或最新 |
| `access_binding` | 固定可信主体和允许范围；`AccessScope` 仍须由服务端权威构造，不能信任浏览器自行声明 |

这些是 Python 协议和合成适配器，不是已安装的 HTTP API。原 `read_revocations` 协议保留；
本轮分页流要求撤销被归一为同一游标空间的墓碑。如果真实来源把撤销单独提供，正式适配器必须
先证明两条流的完整性/一致水位，不能简单忽略撤销流。

**完整性信任边界：**页 ID、边界、顺序和游标检查可以发现结构性重复、错序及漏接一页，
不能证明适配器没有在一个自洽区间里隐瞒事件。测试专门构造了“空 events + 合法终点”的谎报，
证明消费端无法仅靠这些元数据发现该遗漏。因此不输出 `source_completeness_verified`，不把 epoch、
页计数或本轮测试当成真实来源完整性认证；真实接入仍需对权威源实现进行独立核验。

## 4. 扫描、提交、失效与重建

1. 派生索引绑定一个可信访问上下文和来源 generation。主体或允许范围变化时拒绝复用；
   需显式清空派生数据后重建，防止不同主体共享旧投影。
2. 收集同一扫描上界内的所有页，逐页检查扫描 ID、起止游标、顺序、条数、终止条件和预算。
   ACL 过滤的空页允许前进到可信适配器给出的区间末端；不根据最后一条可见事件猜测水位。
3. 同一事件跨页的多次修订先折叠为本轮最后版本，再用 #199 的 `build_projection_card`
   按精确 `expected_revision` 回源。历史旧修订不会先生成一张“当前卡”；撤销只移除派生卡。
4. 全部构造在暂存 dict 中完成。最后校验来源/授权 epoch，并对索引修改序号做冲突检查，
   一次替换卡集合与游标。中途错误、预算耗尽或并发冲突均不提交半成品，也不推进游标。
5. 授权 epoch 改变时从 cursor 0 重建可见集合。这既移除失去权限的卡，也可补回新获授权但
   游标早于旧进度的事件。事件可见范围改变必须被适配器计入授权 epoch。
6. 每次 `read()` 都检查来源 generation、回源核对当前 revision/SHA-256/权限，再做扫描 epoch
   终检。权限撤回、修订、撤销、来源字节/卡片篡改都拒绝并移除本次命中的旧卡；不退回缓存。
7. `clear()` 只清除内存中的派生卡、绑定和游标。原始来源不变；重新扫描能重建相同
   `projection_card_id` 与 `source_refs`，不同 page size 不改变派生结果。

所有卡继续使用 `ProjectionCard` / `projection_card`，`authority="derived"`。
首版仍只有经来源字节哈希验证的 240 字原文字面预览，不生成摘要或情绪推断，不晋升固定身份。

### 本轮尚不提供的能力

- 内存索引的游标**不持久**；进程重启需要清空后重建。本轮不冒充 GM-02 durable closeout。
- 没有真实 G3 事务快照、ACL 凭据、分页完整性证明、广播失效、独立单调下界或外部 C。
- 内存旧数据在刷新失败时可能仍存在；安全读口一定重新回源，不能直接使用 `_cards` 做 UI、
  导出或召回。`progress()` 仅是派生计数，不能用它证明当前来源权限或事件完整。
- 没有实际索引磁盘清理、embedding、情绪浮现、异步队列或自动重试；没有改变 GM-01B 真实接入状态。
- 不实现自动换窗、发送消息或新建用户会话；不以固定 600K 阈值启动任何动作。

## 5. 离线验收

本轮 Python 3.12.14，无额外依赖；合成夹具提供原文、HEAD、权限 epoch 和分页。
新增测试中的 socket connect/DNS 均被阻断。基线文件下载后与 #199 固定 commit 的 Git blob
SHA 核对；新增和修改文件语法解析通过。

```bash
python -m unittest \
  backend.tests.test_g3_projection \
  backend.tests.test_g3_projection_feed
```

**本地：76/76 PASS = #199 原有 40 + 本轮新增 36。** 这是独立开发集合，不是 G3-QU 正式门槛。

| 测试组 | 证据 |
|---|---|
| 三层 / 重建 | 固定、短期、长期；源字节不变；清空重建和换 page size 后卡及来源引用相同 |
| 修订 / 撤销 | 跨页只派生最新修订；增量替换旧卡；墓碑不读取正文；固定锚点撤销无需重新审核 |
| 权限 | 刷新前读取即拒绝撤权卡；epoch 变化清除不可见卡；新授权补回旧游标事件；范围变更不复用主体索引 |
| 页故障 | 重复/错接边界、错序、重复游标、修订倒退、提前结束、不前进、错误 scan ID/类型均拒绝 |
| 原子提交 | 后续页失败不改变卡集合与游标；重试可恢复；同基线并发刷新只允许一个提交；清空不会被旧刷新覆盖 |
| 读边界 | 当前 HEAD 不符、源字节或卡篡改、授权/来源终检变化均拒绝；generation 变化要求清空 |
| 资源 / 边界 | 空源、ACL 空页、重复刷新、观测到游标回退、页数/事件数/条数限制、错误元数据不泄漏私密正文 |
| 信任反例 | 自洽的来源漏事件声明不能由消费端单独证明或识破，不因此声称 source completeness |

默认每页 100，允许 1–200；默认最多 100 页，硬上限 1000；变更和卡集合硬上限各 10000。
超限时整体拒绝，不把截断扫描称为完成。此原型没有真实网络超时/取消协议或线上性能验收。

完整仓库回归以本轮 Draft PR 的最终 commit CI 为准；本地没有宣称运行整个后端。
