# 使用量 · 换窗阶段的离线观测

本增量叠加在账本草稿 #132 上，只在显式安装的账本报告中新增
`rollover_preview`。它是 1,000K 容量方案的参考评估，不是当前生效的
设置、摘要任务、自动换窗调度器或执行授权。

| 当前上下文 Token | 参考阶段 |
| --- | --- |
| 小于 500K | normal |
| 500K 起 | prepare：准备接续包 |
| 600K 起 | switch：默认换窗线 |
| 700K 起 | priority：日常兜底 |
| 800K 起 | emergency：特殊应急，不是日常目标 |
| 达到实际观测上限 | capacity_reached |

只有当前会话的 Token、至少 1,000K 的实际观测上限、来源、带时区时间和
明确非过期状态均存在，且没有未确认工作时，才返回参考阶段和距离。
全会话汇总、缺失/异常数字、容量不足、超过观测上限、压缩失效、
新记录使旧占用过期或未确认请求，均保留 unavailable 和原因。
不根据模型名称或累计用量推测容量，也不把阈值按比例缩到小窗口。

`observed` 仅表示这份观测能评估参考方案，不证明下一轮容纳得下、
生成已空闲、来源已完成生产资格验收或真实模型支持该方案。
时间只作来源追溯；最新性沿用报告对后续请求和压缩的失效处理，
不引入按墙钟时间猜测的“实时”保证。

`automatic_prepare_enabled` 和 `automatic_switch_enabled` 始终为 false。
阶段评估本身不写账本，不生成摘要，不建窗、不发送或中断消息，不改变
已有阈值/时区/金额预算。现有前端可忽略该新增字段；本增量不改前端
页面或启用线上采集。用户最新总表中的页面名称是“归汀 · 使用量”，
后续界面实现沿用该名称。

后续仍需实现可见聊天与底层会话的关联、接续包、生成边界的调度、
幂等消息归属、失败恢复、旧原文搜索/回跳与重要记忆的独立验证。
本评估通过不能视为无缝换窗完成。

离线检查：

```bash
python -m unittest backend.tests.test_usage_ledger_rollover
```

测试使用临时 SQLite 和合成观测，覆盖阈值两侧、真零与未知值、来源与
时间、模式/会话隔离、压缩与过期、未确认工作、用户设置保留和读取无
写入/无网络副作用。默认关闭、v48 与 36/36、108/108 门槛保持不变。
