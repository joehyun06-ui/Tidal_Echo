## 2. 身份、有效性、可备份性、可恢复性，四个彼此独立的判断

| 审核门禁 | 允许未来单独申请的最小动作 | 允许外部显示的脱敏结果 | 当前状态 |
|---|---|---|---|
| **G1A 文件身份** | 需业主新增授权后，操作员仅在受控 Render 环境中把 11 个候选与用途/所属服务进行本地核对。可以在仅受权的本地界面查看必要文件名，但绝不向聊天、GitHub、CI 展示真实姓名、目录、时间戳、ID 或哈希 | 仅合计数：疑似业务库、疑似历史备份/临时文件、未知、拒绝/不可读；分类依据保留在私有本机，不形成公众可逆标识 | **NOT_AUTHORIZED / NOT_PERFORMED** |
| **G1B SQLite 有效性** | 在 G1A 明确授权边界后，再另行授权少量已确定对象的只读文件头/SQLite schema/PRAGMA；权限范围、时间/资源预算、是否容许只读 SQLite 连接需明确 | 仅各类别的匿名总数和通过/失败/未知状态；不输出 SQLite 表名、schema SQL、记录内容、各文件哈希或 row ID | **NOT_AUTHORIZED / NOT_PERFORMED** |
| **G1C 一致性备份** | 仅当 G1B 验证类型并且业主明确指定文件范围、所有权、私有加密目的地、保留期限后，才可设计 SQLite Online Backup API；源文件仍活跃时禁止简单 `cp`；必须考虑 WAL、sidecar、并发修改及跨库时间点 | 传输完成/失败、私有端校验状态、时间点是否匹配；禁止真实原始数据公开 | **NOT_AUTHORIZED / NOT_PERFORMED** |
| **G1D 隔离恢复** | 在此前各项均独立获批后，才允许使用临时恢复副本、独立沙盒验证读取/迁移/业务关系，网络、Telegram、LLM、定时任务、Codex 回调全部关闭 | 仅脱敏 PASS / INCOMPLETE / FAIL、无法确认的跨库引用数量分类，禁止重新派发任务 | **NOT_AUTHORIZED / NOT_PERFORMED** |

**不可跳级：** 具备 `.db` 或 `.sqlite3` 后缀 ≠ 有效 SQLite；有效 SQLite ≠ 可在线直接复制；一致性备份 ≠ 可重建运行态；隔离恢复 ≠ 完整生产灾难恢复。11 个扩展名候选既不能变成“11 个有效库”，也不能变成“无需备份的缓存”。

## 3. 未来 G1A 所需的额外隐私保护

1. **仅在新增授权后**才允许实际观察文件名和用途。不得把 Stage47 输出扩展为列举根目录文件名；不能从当前“请继续”推定许可。识别本身虽可能只读，但文件名常含用户、会话、凭据或业务标识。
2. 不要将真实文件名做 **未加盐 SHA-256** 后传到 PR/聊天。已知候选或小词典可能反推出原名；也不要返回固定可跨轮关联的匿名 ID、路径、单文件精确大小、修改时间或十六进制头字节。优先只输出聚合统计，且不输出少量敏感类别的细分例子。
3. 在业主私有环境内部，暂时的路径/用途对照表才可用于受权对象的实际识别，不上传、不进入 Git、CI、云同步目录，不写包含敏感内容的日志。任何本机隐私文件的保留和销毁由单独批准确定。
4. 只处理普通文件；目录/符号链接/硬链接/跨设备路径/竞态变化需拒绝或标记未知，操作代码必须使用固定根目录 + nofollow 的目录描述符、条目上限和超时；禁止递归遍历不明目录或读取认证文件。
5. 实际审计前后数量、类型变化时，**停止而非重试、忽略或自动扩张**。Stage47 的 11 项仅是 `2026-10-29` 那次快照，不是永久固定的生产磁盘事实；要获得新的身份核查授权必须明确漂移策略。
6. 同一业务同时具备 SQLite 主库、WAL 或另外时间点的 `relay.db` 恢复副本时，要验证的是**整个文件家族与数据库一致性**，不是随意混合跨时间点文件。即使单独库通过 SQLite 检查，跨库消息 ID、任务租约、回调幂等仍需额外恢复门禁。
7. `GUITING_LEDGER_MODE`、`GUITING_LEDGER_PLAN` 和签名密钥的启用/存储状态仍未确认，不允许根据 11 个候选类别猜测其中某个属于账本；若将来需要查询实际 mode 或 plan，需要单独限定批准，不可输出值为 secret 的项。
8. Codex Home 包含未知敏感状态，**不在本次 11 项身份调查范围内**；即使确认了某条业务库，也不能据此自动读取 Codex Home、密钥或线程数据。
