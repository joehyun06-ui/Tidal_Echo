# Web 发送收件关联

POST /app/send 可选接受严格小写 UUID v4 格式的 client_request_id。格式无效时在持久化或分发前拒绝；未提供该字段的旧客户端保持原有行为。编号随 canonical 人类消息的 meta 一起落入既有 messages 表，并沿原 app_payload 路径出现在鉴权历史与 SSE 中，API 与 Codex 均保留原入站路径。

此编号仅用于客户端将本机待确认发送与既有服务端原消息关联。它不是幂等重试键，不防止调用方再次显式提交，也不触发任何核对后的补发。读取历史不调用模型；消息入库、模型接收、回复完成、记忆保留不能互相替代证明。

不新增路由、索引、表、秘密或生产参数；不改变频道、正文、附件、上下文快照、生成与记忆形成策略。回退后端后新发送不再回传编号，客户端保留待确认与人工核对入口；既有编号元数据仍属于原消息记录。

验证涵盖鉴权、格式失败前零消息落库、旧客户端兼容、实际临时 SQLite、历史/SSE 附件与编号。配对前端在独立分支完成丢响应刷新恢复、重复/错误编号与分页检查，真实模型请求保持禁用，v48、36/36、108/108 不变。
