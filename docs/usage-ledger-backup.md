# 账本原生备份与隔离恢复演练

本批只在临时目录和合成 SQLite 上执行。没有复制生产数据库，没有读取生产聊天、
记忆正文或认证文件，没有恢复 Render 磁盘、部署、重启或调用模型。v48、36/36、108/108
继续冻结。现场已看到磁盘快照，不等于数据库一致性恢复已验收。

## 已实现的范围

`backend.usage_ledger_backup.snapshot(source, destination)` 是供可信维护代码显式调用的
独立函数，不读取环境变量、不安装 HTTP 路由、不创建定时任务，也不加载生产入口。

- 来源必须是已存在的独立账本，以 SQLite URI `mode=ro` 和 `query_only` 打开。校验
  必需表/列，并拒绝同时含有 `messages`、记忆表等非账本表的混合数据库；不初始化来源。
- 使用 Python `Connection.backup`，由 SQLite 复制一致快照，包含未 checkpoint 的
  已提交 WAL 内容，不通过只复制主文件来猜测一致性，也不主动 checkpoint 来源。
- 目标必须是绝对路径、尚不存在的新文件，父目录权限只允许所有者访问。新文件以
  0600 独占创建；拒绝来源、已有文件、主文件/辅助文件名称冲突、已有目标辅助文件和
  叶子符号链接。已有文件不会被覆盖。
- 仅把新目标转为 DELETE journal 模式，验证 schema、`integrity_check` 和
  `foreign_key_check` 后同步目标文件。来源和目标错误只返回固定类别，不输出路径、
  SQL 错误、原始用量或内部签名材料。
- 备份步进和目标校验设有协作式期限；无自动重试。失败时仅清理本次创建且文件身份
  仍一致的主文件，不删除已有文件。它不是系统调用的硬实时上限，也不承诺崩溃时无残留。

`isolated_restore(snapshot)` 始终创建新的临时私有目录，只在其中恢复并在结束后清理。
没有传入生产目标的参数，没有“覆盖正式库”或“恢复后启用采集”的选项。

## 离线命令与验证

```bash
python -m backend.usage_ledger_backup --mock
python -m unittest backend.tests.test_usage_ledger_backup
```

命令行只支持 `--mock`，没有 `--source`、真实路径、部署或启用参数；全部数据库由演练
自行在临时目录创建。没有任何命令应直接指向 `/var/data/relay.db` 或记忆库。

演练覆盖：

| 项目 | 验证结果的含义 |
|---|---|
| 未 checkpoint 的已提交 WAL | 恢复得到已提交行；源主文件和 WAL 字节保持不变 |
| API/Codex 模式 | 保留模式分隔，不为 Codex 生成 API 缓存或费用 |
| 历史用量与价格 | 保留原归一化数据和价格快照，不按新费率重算 |
| 签名分页 | 数据库内游标密钥及 revision 被复制，原快照游标可继续核对 |
| 设置、清理与退役 | 保留设置 revision、原始用量过期标记及已有删除/拒绝迟到写入标记 |
| 未确认/停采 | 保留 journal，不把恢复当成采集完整或零消耗 |
| 续窗回执 | 保留 HMAC 绑定与幂等状态；仍需要原来的外部运行时 HMAC 密钥 |
| 原生通知 | 已记历史保留；新采集器首次不能沿用旧运行时基线，后续连续观测才重新建立 |
| 故障与目标保护 | 缺源、坏库、混合库、已有目标、辅助文件冲突和期限失败不会变成成功 |

输出始终声明 `basis=disposable_mock_only`、`production_verified=false`、
`enables_production=false`、`production_restore_supported=false`。外部线程独占与真实
CLI 通知连续性也保持未验证。离线通过不消除这些缺项。

## 旧备份、删除与密钥的边界

旧快照不知道备份之后发生的删除、完整清理、授权变化或配置更新。测试专门证明：
旧副本可能仍有后来已删除的合成记录。因此本工具只恢复到隔离目录，不能把校验通过的
旧副本直接接回正式服务。正式恢复方案仍须核对更新的删除/保留记录、会话权威及
运行时连续性；相关核对方案未完成时保持停止采集，不能用旧游标和旧回执推断当前授权。

账本文件含原始用量、请求身份、签名游标密钥和 HMAC 回执，不是去敏导出。数据库
原生备份复制数据库内容，不提供自动加密、离机存储或备份保留调度；逻辑删除/过期也
不保证历史备份和空闲页中的旧内容被物理清除。不得把原始备份提交到 Git、报告或浏览器
导出。实际备份位置、加密、访问控制、过期和销毁流程仍需受控运维验收。

续窗 HMAC 密钥来自运行时，不应加入备份清单正文或日志。恢复时不能重新生成该密钥
后宣称旧回执仍有效；测试验证错误密钥会被拒绝。数据库完整性检查不是备份来源认证，
也不证明价格、记忆或实际账户账单真实完整。
