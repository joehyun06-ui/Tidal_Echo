# 账本组合与连续性离线验收

已有组件整理为 `backend.usage_ledger_composition.LedgerServices`，候选入口已加入默认
关闭接线；线上配置、模型协议、提示词或记忆策略未改变。仍为独立草稿，未合并/部署，不发真实模型
请求，不读生产数据；v48、36/36、108/108 保持冻结。

## 组合顺序

1. 调用者提供独立账本绝对路径、relay/native 来源路径，以及运行时取得的续窗 HMAC
   密钥。构造 `LedgerServices` 前先核对路径，禁止账本与来源库互为同一路径、符号链接、
   硬链接或父子路径。不会创建来源库/目录；配置校验失败时不创建账本。
2. 采集端显式提供 `api_profiles` + `fingerprint_key` 才创建 API 采集器；显式提供
   `codex_provider_id` + 固定 schema 版本 + native 库才创建 Codex 采集器。
   默认两者均为 None。HMAC 密钥不放 JSON、代码配置模板或输出中；测试仅用合成密钥。
3. 在创建已有 runtime 时，显式展开 `api_runtime_kwargs()` / `codex_runtime_kwargs()`。
   不修改已经运行的对象，不增加工作进程、模型请求、SDK 或 RPC。原生后台核对仍由
   `StreamingCodexGenerationRuntime` 的现有任务执行。
4. runtime/integration 建好后，`bind_authority(authority, session_lock,
   create_session=integration.create_web_session)` 绑定同一权威来源、创建/删除锁与原工厂。
   绑定前来源返回不可用；禁止二次绑定，权威来源声明的 relay 路径必须与组合一致。
5. 原上下文路由安装器显式接收 `**services.action_kwargs()`；普通删除可显式调用
   `services.delete_session`，消息版本删除安装器显式接收 `**services.deletion_kwargs()`。
   均复用已验收逻辑，不添加浏览器账本写入或破坏性维护端点。
6. 离线测试保留独立读取实例，共用同一账本和来源路径。候选生产读取端放在 loop，
   统一使用其真实权威来源，显式 `install_reader(app, check_auth=..., prefix='/loop')`，
   relay 只鉴权并转发。重复路由（包括不同参数名）在挂载前拒绝。

这些函数不会因配置预检结果为 true 自动调用。`usage_ledger_preflight` 仍只是声明核对，
不能授权安装。实际部署的两个进程不能共享 Python 对象；候选接线让 loop 独占会话权威，
relay 通过固定内部协议读取。候选 relay/loop 已按显式 mode 安装，线上未部署；启停与转发细节见
[候选接线与回滚](usage-ledger-startup.md)。

只有可信服务端负责装配。读取端的 authority 不能来自浏览器声称的 provider；
check_auth 必须沿用真实鉴权。路由注册顺序、跨进程权威适配器、实际挂载、磁盘可写与
备份策略仍需部署审阅。本批的路径检查无法保证启动后的路径替换/文件系统竞争，
也不证明物理持久盘正确；应由部署权限与持久挂载管理这些条件。

## 配置变化与回滚边界

- 不提供热修改采集器的接口。路由/模型/协议/价格变化应准备新的不可变配置，并审阅
  完整主/备用路由清单；未匹配的新路由保持缺口，不能按旧模型价格估算。
- 离线测试同时保留旧采集器的进行中请求与新实例，确认旧请求按原快照结束、新请求
  用新快照。实际进程切换中未结束的请求仍可能留下未确认标记；不自动重试模型。
- 同一路径重开保持原账本、签名游标、清理水位和删除标记。不会从旧聊天回填消耗，也
  不用原账本重放建立新进程的 Codex 连续基线。
- 回滚采集应回到原本未注入的组合，并保留独立账本；不自动删除数据、不回算历史价格。
  已在途请求的终态是否可达应继续按已观测结果记录，不能承诺无损切换。
- 续窗回执密钥需跨服务实例/重启保持一致。密钥变化时旧回执无法验证，不猜测原文，
  也不重建/重发目标会话。前缀密钥变化还会影响缓存键，需单独审阅。

## 已完成的合成场景

| 场景 | 验收结果 |
|---|---|
| 采集/读取独立实例 | 同一临时 SQLite 中，读取端看到真实开始标记与终态；自身不创建采集 run |
| API 中途退出再重开 | 旧请求保留未确认，新请求不把旧请求清零或标成失败 |
| 两次实际 Python 子进程启动 | API 未确认标记跨进程保留；Codex 第二进程不把线程累计量伪作单轮量 |
| 原生通知重放/下一轮 | 重放不重复入账，不作为新基线；首次重开后单轮不可用，后续确切连续边界才恢复 |
| 漏掉 durable 中间轮次 | 下一轮保留原始用量，拒绝跨缺口差值 |
| epoch、模型、共享线程变化 | 阻断跨边界推算；API 费用与 API 缓存在订阅模式仍不适用 |
| 进行中请求与新配置并存 | 原费率/版本保持不变，调用方修改价格字典不改变已复制的快照 |
| 删除与迟到完成 | 普通会话/消息版本删除沿用真正删除钩子，旧采集器不能恢复账本 |
| 挂载与鉴权 | 实际 ASGI 读取需认证，未知会话不接受，响应 no-store，重名路由不重复安装 |
| 前端真实动作 fixture | 改用独立组合实例，继续验证手动压缩、续窗草稿、分页、导出、删除与迟到写入 |

离线测试命令：

```bash
python -m unittest backend.tests.test_usage_ledger_composition
```

以上只证明给定合成场景的行为。子进程测试不会启动 Codex、登录账号或发送请求；通知由
合成数据直接交给原采集器。真实 CLI 通知连续性、线程独占及正式账户用量仍未验收，
无异常不代表完整账单。跨聊天/账本存储删除仍非分布式事务，故障时需同一删除请求核对。

另已加入[通知连续性的真实 JSONL 离线传输验收](usage-ledger-native-notifications.md)：
合成子进程经过共享 reader 与原运行时回调进入账本，并覆盖 EOF、协议错误、重连、
重放及迟到/无效用量与核对并发。仍未运行真实 CLI。迟到用量会作废已经开始的同线程
后继基线，其他线程保持独立；已落库的原始观测不被改写，异常单独保留。
