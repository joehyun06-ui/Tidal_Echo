# 归汀 · 跨进程一次性确认票据（离线隔离草稿）

叠加在 PR #138 上，**仍然默认关闭、不接 HTTP 路由、不实际写记忆、不声称有真人确认或生产级竞态防护**。

独立模块 `backend/memory_shared_confirmation_ticket.py`。仅 `MEMORY_SHARED_CONFIRMATION_TICKETS_ENABLED=true` 且 `MEMORY_TRUSTED_AUTH_EPOCH_ENABLED=true` 时使用；所有测试仅短暂设置合成值。

- 与 PR #138 的登录纪元注册表共享**同一个 SQLite 文件**。用 `BEGIN IMMEDIATE` 对票据领取、登录纪元的检查及并发撤销进行原子串行化。
- 120 秒票据、最多 8 个待领取。SQLite 仅保存票据 SHA-256、登录纪元 SHA-256、主体/登录/会话/请求 ID、预览摘要与状态；**不保存票据明文或记忆正文**。领用后留下 `consumed` 状态（定期清理）。
- 请求必须来自已认证的服务端可信组件；`TrustedTicketContext` 数据类型不能作为认证证据。票据只能证明内部内容确认的一致性，固定确认短语不能证明人类点击。
- 有效票据一经领取，无论摘要或确认短语正确与否，均被消耗；其他工作进程、并发请求和进程重启都不可重复领取。认证或会话变化、退出/重登导致的纪元轮换会拒绝领取。
- **仍未达到实际写入条件：** 领取的 SQLite 事务结束后，未来的记忆写入可能发生在另一事务；因此撤销可能介入领取成功与写入提交之间。此模块不调用写入 service、无 HTTP/API 路由、无实际真人同意授权、无跨进程写入回滚或故障恢复。生产必须将撤销条件与最终写入的不可逆边界进行同一事务验证或等价的可证明协调。
- 有效认证快照、登录关联、登录纪元的可信存储仍需真实身份服务提供。不得把 Header/Cookie 原始声明视为可信，禁止浏览器写入或外网部署。

独立合成测试：`python -m unittest backend.tests._memory_shared_ticket_worker -v`。验证并发单次领取、独立进程读取/领取/重放拒绝、错文案/摘要、跨账号/会话、退出/重登撤销、120 秒严格到期、全局容量、默认关闭和不存正文。先完成 PR #138 的 Windows CI 修复验收，才考虑后续合并路径。
