# 手动续窗创建结果核对

创建新窗的 HTTP 响应丢失时，浏览器保留原请求，不以新 UUID 再次创建。用户可以显式调用 `POST /app/sessions/{source_id}/continuation/reconcile`；relay 只转发一次到同名 `/loop/` 路由。请求体仍为原 `request_id`、`source_version_id` 与 `text`。

核对端点复用当前鉴权、会话归属、所选消息版本、provider 与私有禁止缓存规则。它只能读取已有创建记录，校验同一 HMAC 密钥、原文摘要、来源和目标；必须已经跨过持久化的 factory 调用标记。没有记录或没有权威目标时保持未确认，不预留新 UUID、不调用 factory、不创建模型线程、不发送草稿或请求推理。

目标存在时可以补登记原续窗关系。创建记录和续窗账本继续只存 ID 与 keyed digest；核对并不证明草稿已送达、首条回复完成或重要记忆保留。删除、清理、密钥改变、版本切换或摘要不匹配均不能被成功响应掩盖。端点与现有创建接口共用 160 KiB 请求体上限；错误也返回 `private, no-store`。

前端在发送创建请求前，把原 UUID、版本、provider 和用户核对的续窗包写入现有按连接隔离的本机草稿存储；保存失败即不发起创建。刷新与重连只恢复待确认标记，不自动提交任何 POST。用户点「核对创建结果」后，只使用此核对端点。损坏的本机记录显示不可用，并阻止另起创建请求。

恢复到确切目标前，前端同步目标历史，检查已有用户消息、生成、附件、待发送内容及不同草稿，避免覆盖。只有空闲且不冲突时才恢复原续窗包为草稿，完成持久化后再清除来源待确认记录。仍需用户确认发送。身份变化清除界面；退出设备并清除数据会移除本机草稿和待确认记录。后端未接入创建回执时保留原有复制/手动查看会话列表的降级方式，不宣称支持刷新恢复。

无需新增生产参数或 schema 迁移；复用已启用的 Ledger 接线和原持久化 continuation key。不能轮换该密钥来处理未知结果。此变更属于手动续窗恢复，不启用自动摘要或同一可见聊天里的无缝底层换窗。

离线验证覆盖 factory 结果未知、进程重启、创建标记、并发核对、原文/来源/版本/密钥冲突、清理、鉴权、体积与禁止重试。前端验证实际 IndexedDB 刷新、同一 UUID、已用目标与草稿保护、身份变化；全部来源和密钥为合成值，未发送真实模型请求。
