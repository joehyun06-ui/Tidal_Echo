# 归汀 · HTTPS 发送器真实 TLS/CA 信任验证（本机离线）

堆叠已验收的 Draft #154。本轮不修改 `backend.app`、登录、#151 实际发送器或记忆 UOW，只在独立专项中用**真实 TLS 握手**验证 #151 的 `_PinnedHttpsConnection` 及上层发送器的校验边界。

测试在 Windows、Linux 的本地 `127.0.0.1` 随机端口启动临时 TLS 服务，进程内生成一套独立测试 CA 和叶证书。客户端保持服务端固定域名 `login.example.test` 用于 TLS SNI/主机名匹配；`socket.create_connection` 由测试严格拦截，只接受发送器已经锁定的合成公网地址 `8.8.8.8:443`，但实际拨号只连接本机回环端口。不会做公网 DNS 解析或 TCP 连接。临时证书/私钥仅写入操作系统临时目录，全部测试结束后删除，不提交或打印到仓库和日志。

验证内容包括：
- 独立受信测试 CA 签发、SAN 匹配的证书可真实完成握手，观察到 SNI 原始域名，取得 HTTPS/HTTP 响应。
- 另一个不受信任的 CA、证书 SAN 主机名不匹配、过期服务器叶证书均被 OpenSSL 的 `CERT_REQUIRED` / `check_hostname` 拒绝。
- `_PinnedHttpsConnection` 的数值 IP 拨号不将 `8.8.8.8` 当作证书名，不进行任何第二次域名解析。
- 上层 `PinnedOidcHttpsSenderReview` 使用同一真实握手后仅返回受限响应对象；证书验证异常在上层统一转换为无敏感数据的拒绝错误。上层仍必须显式满足原本三重离线测试开关，不允许绕过原有默认 OFF。
- 测试在关闭发放、登录、真实 IdP、付费 API 和记忆写入的前提下执行。实际客户端根证书通过测试注入；**不**改造或关闭生产系统 CA 信任。

本次实际完成的是**本机证书链与主机名验证**，并不证明公网证书链、OCSP/CRL、真实 IdP、可信反向代理、DNS/代理网络环境、浏览器身份登录或人工同意。上一阶段真实浏览器测试采用自签名证书并忽略错误；本轮补的是 Python TLS 发送器的实际校验，不应混为 WebKit/Chromium 生产 CA 验收。

所有 PR 保留 Draft、未合并、未部署，v48 36/36、108/108 正式门槛不变。
