## 0. 只读核对的现状（不混淆证据等级）

- 生产控制平面只读核对：Render `ouou-home-telegram` 最新 LIVE 提交 `49ebe9a0e7f391efda86585b2bbe8f1bcff4288f`；`autoDeployTrigger=off`；原持久磁盘挂载 `/var/data`。这些是服务配置和部署事实，不证明服务器数据内容、文件系统种类、inode 所属 UID 或运行时能力。
- 冻结版本的 `scripts/render_start_p3.py` 是服务启动包装器；审阅该文件未发现一个既存的、经授权的、可在运行中以磁盘所有者身份执行匿名数据库审计的运维接口。静态仓库源码不能证明实际进程 UID、目录 owner 或运行时支持其他入口。严禁为此打开新 HTTP/IPC 管理入口。
- Stage50 G1A 用户提供匿名报告：11 个扩展名候选 + 4 个未知目录，11 个全部没有可靠名字线索，真实 SQLite 和业务身份仍未知。
- Stage51 G1B-1 用户运行固定版本 `3a52285aa6d12b9b43a05b95af0b5c37ff4573ff` 返回 `STOP_READ_NOT_SAFE`；停止码没有表明哪一个系统调用或实际 errno，也不能证明此前零字节读取。
- Stage52 P0 用户返回 `/var/data` 根所有权与 SSH 有效 UID 为 `MISMATCH`；P0 不打开/枚举目录，不知道候选所有者。
- Stage53 P0C 用户返回当前线程有效 `CAP_FOWNER=NO`；不接触磁盘。这些诊断发生于不同时间/进程，不能冒充对 Stage51 当时权限和失败系统调用的原位证明。
- Linux `open(2)`：`O_NOATIME` 要求 eUID 为目标文件所有者，或进程在用户命名空间内具备符合映射要求的 CAP_FOWNER；且该标志并不保证所有文件系统上有效。两项结果高度支持根目录 NOATIME 权限不适用假设，但不能宣布根因已被内核日志证实。

## 1. 不变的安全目标与数据边界

**最终业务目标**：若未来真的存在合规路径，仅做 Stage51 G1B-1 的最小 SQLite 文件头格式提示；这不是数据库身份、SQLite 完整性、备份资格、Ledger 激活或正式恢复验收。

- 固定生产根 `/var/data`，必须复用 G1A 的固定排除清单、严格 11 个根目录单链接普通 SQLite 扩展名候选 + 4 个普通未分类目录、两次匿名元数据快照和失败即停；不跟随软链接，不递归、不开其他文件。未知/漂移 STOP，不允许改变数量以绕过。
- 成功后每个候选只读最多 100 字节头，**不打开 SQLite 引擎**；不得读 SQLite Schema、SQL、表或记录、WAL/SHM、四目录正文、密钥、配置，也不得进行复制、传输、备份、恢复。
- 原始文件名、文件头字节、inode、UID、GID、路径、哈希、大小、时间戳及错误详情只允许存在必需的短时进程内存，不得回传聊天、GitHub、CI、日志或归档；仅返回匿名聚合计数。
- 真正的零源修改门禁不仅是“没有写代码”：必须避免读操作产生的 atime 写入，保证打开/枚举目录和候选的文件系统与权限条件，且不能创建 WAL/SHM/临时文件、socket 副作用或服务启动/重启。
- 仍需在实际权限/运行时/文件系统上论证元数据读取的安全性；`O_NOATIME` 是必要的控制手段，但**不是跨所有文件系统的无副作用证明**。

## 2. 路径决策矩阵

| 候选路径 | 是否可立即执行 | 安全分析 | 当前决定 |
| --- | --- | --- | --- |
| A. 现有 SSH 会话直接重跑 G1B-1 | 否 | 根目录 eUID 不匹配、当前 CAP_FOWNER 无有效位；原运行已因安全门禁停止 | **禁止** |
| B. 某个**既存且经授权**的、运行在同一挂载实例内的所有者匹配执行上下文 | 尚无法证实 | 需要证明其无提权、无重启、无注入/管理入口、拥有正确目录/候选 DAC 权限和 noatime 保证，且能执行已审定程序；目前没有这种入口的证据 | **条件保留 / 默认不可用** |
| C. Render ephemeral shell / one-off job / build / predeploy | 否 | 持久磁盘只在附加服务实例运行时可用，构建、预部署和 one-off job 不可假定可访问；临时实例不能作为原持久磁盘审计通道 | **不采用** |
| D. 修改 owner、chmod、capset、sudo、改变 eUID、执行 sudo/su、挂载参数、capability 设置 | 否 | 违反只读和不提权前提，可能影响活跃服务，且无单独授权 | **禁止** |
| E. 去掉 O_NOATIME 或使用一般 O_RDONLY、O_PATH 后改读其他接口 | 否 | 去掉 NOATIME 可更新源 atime；O_PATH 本身不能满足后续文件头读取；不能将其伪装成零副作用方案 | **禁止自动降级** |
| F. 官方快照、SCP、复制到隔离环境、在线备份、恢复到其他实例 | 否 | 属于 G1C/G1D 或真实生产文件导出，当前未授权；也不是现有直接零复制审计路径 | **锁定** |
| G. 无新增读取，延续现有元数据审计结论 | 是 | 不引入生产变更，保留 G1B-1 已停止、身份未确认 | **当前默认选择** |

## 3. 有条件的路径 B：若将来发现预先存在的合法执行上下文

以下全部是**必要前置证据**，并非已存在某条可行路径的声称：

1. **载体已存在**：由可信的生产运维契约/平台文档证明执行位置是附加原 `/var/data` 的原服务实例，不是独立副本、构建/预部署、一次性任务、临时隔离实例。不得新增公共管理端点或 IPC，不得注入现有服务进程、重写启动命令、更新环境变量、重启、重新部署、禁用服务保护。
2. **权限事前可证**：执行代码的实际 eUID 与根目录所有者以及全部 11 个候选的普通权限（DAC）相容，或具有在现有政策内的合法权限且不经提升；不得仅凭 Stage52 不同时间的 SSH 观测或文件扩展名推断。如果要做新的生产 UID/文件元数据核对，需**独立范围授权**，不得暗中执行。
3. **文件系统事前可证**：可信的环境/提供商文档证明该具体挂载的 O_NOATIME/目录枚举语义足以满足零源修改要求；不能把“Linux 上有 O_NOATIME 常量”作为完整证明。未知文件系统、NFS 或特殊代理行为 → STOP。
4. **代码完整性**：保留 G1A 固定范围和身份/类型/链接/快照保护，进程实际运行的是经过离线审查和精准 SHA 锁定的 G1B-1 代码；不得引入文件名输出、内容读取回退、数据库引擎、网络上传或持久化日志。
5. **并发与副作用评估**：不扰动活跃 Telegram/relay；无法建立读取期间关键元数据不变性或进程/平台 I/O 语义时 STOP。单次前后检查不证明全局一致性，不能据此做 SQLite 数据有效性结论。
6. **重新授权**：所有证据、威胁模型和合成测试通过后，必须单独批准**新的执行上下文和这一次生产 G1B-1 读取**；原 Stage51 STOP 后的授权不得自动迁移到其他身份/入口。

任何一项不满足 → 路径 B 判定为 `NO_APPROVED_EXECUTION_CONTEXT`，保持冻结，不试探实际候选文件。

- 未来如果新建执行工具，必须独立 Draft PR、精确 SHA、Windows/Linux 纯合成 CI 和隐私输出审查；**本 Stage54 PR 只有文档，不提交运行脚本或 GitHub Actions 工作流**。

## 5. 决策规则与可审计退出码（设计字段，不是生产结果）

决策结果只能是：

- `HOLD_NO_SAFE_PATH_PROVEN`：目前唯一合理结论，未证明有可用且被授权的执行上下文。
- `CANDIDATE_PATH_NEEDS_INDEPENDENT_REVIEW`：仅已有文件/平台文档提供某一候选执行通道，不表示已可使用。
- `STOP_NOATIME_OR_OWNERSHIP_UNVERIFIED`：任一权限、文件系统或零副作用条件不能证明。
- `STOP_SCOPE_DRIFT_OR_IDENTITY_UNVERIFIED`：若未来另获权执行，候选集合漂移、单文件状态异常或身份线索不足则立即停止。

不得发布 `G1B1_VALID_SQLITE`、`RECOVERABLE_DATABASES`、`LEDGER_ACTIVATED` 等越界字段。状态汇总只说明架构设计许可，不生成真实文件头统计。

## 6. 现在的结论和冻结门禁

**当前 Stage54 选择路径 G：HOLD_NO_SAFE_PATH_PROVEN。** 既存、所有者匹配、无提权无重启的可控执行路径目前没有独立证明；因此没有生产执行脚本，也不应发 SSH 命令。Stage51 G1B-1 仍为 STOP。

- G1B-2（SQLite Schema）、G1C（备份）、G1D（隔离恢复）均继续锁定；11 个扩展名候选未获数据库身份/有效性确认。
- Stage50–54 审计 PR 保持 Draft、未合并，Render 生产版本和自动部署不因本 PR 变化；v48 正式 36/36、108/108 冻结门槛不变。
- 若后续任何单独授权与此文档冲突，以更窄、可审核的安全边界为准，不隐式升级权限。
