# Codex conversation plugins · 0.160.0

New Codex conversations register two fixed App Server dynamic tools: `guiting_plugin_list` and `guiting_plugin_call`. The first returns the current turn's selected tool catalog; the second delegates one exact named tool and arguments to the existing application MCP adapter. No native MCP servers, filesystem/command tools, apps or environment credentials are enabled. The generation hardening profile still overrides caller-supplied tools and configuration.

Selection defaults off, is shared across visible message alternatives, and takes effect on the next message. Each turn discovers only selected public HTTPS Streamable HTTP plugins and freezes their configuration, schema, selection and credential revisions. Every actual call requires a separate user decision. The adapter retains its bounded schema subset, text-only results, public-address pinning and no-retry execution rules. OAuth, custom authentication headers, STDIO and legacy SSE execution remain unsupported.

The native request uses the CLI's `item/tool/call` fields `threadId`, `turnId`, `callId`, `namespace`, `tool`, `arguments`. A response contains `contentItems` of type `inputText` and a boolean `success`. Tests validate both directions and registered definitions against JSON schemas generated by the installed 0.160.0 binary; no model inference is required. Official protocol reference: https://learn.chatgpt.com/docs/app-server.

The JSONL reader dispatches only this explicit handler without waiting on user interaction. All other server requests retain the default rejection. Exact durable job/thread/turn correlation precedes a proposal; a short bounded wait handles tool requests that arrive before the turn-start reply is recorded. Calls are serialized, native call IDs are unique per message, and a turn permits at most eight actual plugin calls. Approval/execution waits pause the active model timeout with a separate 900-second total extension; individual approvals expire after 600 seconds.

Native receipts live in `web_mcp_codex_actions`, separate from API action recovery. SQLite attaches the Codex job database while checking authority and claiming a call. A one-use confirmation cannot authorize another turn, changed arguments, changed plugin settings or changed credentials. Stop cancels outstanding proposals immediately. Shutdown/restart cancels unexecuted calls and marks dispatched calls unknown; late results cannot overwrite that state. Recovery never resumes plugin execution automatically. Results and final answers remain in the same visible conversation.

The pinned CLI exposes `dynamicTools` only on `thread/start`. The application records which native threads were created with the bridge. Existing native threads lacking that registration show `codex_new_session_required`; their history and normal chat remain available. Forks inherit capability only from a registered parent. New native sessions can select plugins before their first message. The fixed bridge definitions let later messages change the selected catalog without modifying native thread metadata.

Session routes stay authenticated and `private, no-store`; the PWA reads provider capability from the server. Deleting a conversation removes its plugin selection and native action content through the existing deletion transaction. No memory retrieval or independent memory evaluation settings are changed.
