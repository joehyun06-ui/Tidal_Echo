# 归汀 · 记忆确认票据的认证主体绑定（独立评审）

状态：**仅内部实验。Draft PR #137（新开），基于 #136。默认关闭、无 HTTP 写入接口、无实际用户认证对接、未部署。**

## 已实现的认证上下文约束

`SessionWriteConfirmation` 的输入从 `session_provider() -> (session,rows)` 升级为 `authorization_provider() -> AuthorizedSessionContext`。必须由**受信任的服务端认证边界**提供以下信息：

| 字段 | 来源要求 | 用途 |
|---|---|---|
| `principal_id` | 登录验证后的服务端主体标识 | 准备与确认必须相同 |
| `auth_epoch` | 服务端新登录时生成的不可预测随机纪元，退出/撤销时必须轮换 | 防止同一个账号重新登录后使用旧票据 |
| `session_id` | 服务端明确指定的活跃会话，不允许聊天 fallback | 与记忆 `scope_ref` 完全一致 |
| `canonical_sessions` | 同一服务端认证上下文的只读会话快照 | 再验证会话存在且唯一 |

数据类的 `repr` 隐去上述字段。调用者不能从请求 JSON、URL、prompt、转发的 header 中任意提取 `principal_id` 或 `auth_epoch`，否则这一层绑定形同虚设。**现有共享单用户 Bearer 并不能自动提供这里要求的、可撤销的每次登录身份纪元**；因此本 PR 仍未接入任何 relay/loop 请求路径，也没有允许用户实际保存的 HTTP 端点。

## 安全语义

- `prepare()` 前验证认证主体、纪元格式、显式会话及 session rows；从可信供应器读取，而不是接受客户端提供的 session 身份。
- 待确认的进程内票据同时绑定 **主体 + 认证纪元 + 服务端会话 + 内容与请求摘要**。
- `confirm()` 每次重新调用认证供应器；任一身份、纪元、会话变化或消失都拒绝，票据不可重用。验证通过后才调用既有 #134 SQLite 写入事务及 HMAC 终态。
- 单用户、无授权撤销纪元、多 worker 或生产故障恢复仍属于**明确的未完成阻断项**，不能据此启用实际写入。
- 当前前端 PR #33 的“确认演练”只是本机 UI 排练，不发送票据或数据。后端实验的 `CONFIRM MEMORY` 也不是已实现的人类授权证明。

## 可执行离线验收

`python -m unittest backend.tests._memory_session_confirm_worker -v` 检验：同一个用户退出再登录（纪元轮换）、换用户、供应器返回错误/非类型化数据、格式错误、拒绝后防二次提交、真实 SQLite 零行副作用以及旧的幂等/来源隔离测试。所有输入与数据是虚构的。

要进一步对接前端仍须独立提交：正式的用户认证上下文、HTTP 路由（明确同意、Origin/CSRF、限流）、跨 worker 一次性票据与撤销、崩溃后账本审计及成功/不确定回执契约。**不得通过提前打开此实验开关来跳过这些门槛**。
